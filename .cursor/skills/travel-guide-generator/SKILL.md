# 旅游攻略生成器

**目标**：理解用户需求，产出符合用户需求的旅游攻略（逐日、逐段、信息完整、可执行）。

**流程**：信息收集（多轮+完成度）→ 资料搜集 → MD 输出与确认 → HTML 生成。

---

## ⚠️ 执行原则（必须遵守）

| 原则 | 必须 | 禁止 |
|------|------|------|
| **逐日** | 一天一天做，每天独立行程区块与时间段 | 合并多日为「几天概览」或省略某天 |
| **逐段** | 每天内一个一个时间段分开执行（搜集与输出均按段推进） | 半天或一天笼统写成一段 |
| **每段完整** | 每段含：核心行动、最优项（名称/理由/位置/人均或票价/开放时间）、**≥3 个备选**、📍💰⚠️；涉及交通/预约/避坑的必须检索并写入 | 缺核心行动、最优项或备选不足 3 个；模糊时间段（如「上午」「下午」） |

**时间段格式**：一律「HH:MM – HH:MM」；半天拆成 **≥2 段**。详见阶段三。

---

## 易用性

- **触发**：「帮我做 xxx 攻略」「按攻略 skill 来」→ 首轮给阶段说明 + 完成度 0%，问 1～2 项（目的地、日期）。
- **阶段话术**：切换时明确告知，如「信息已够，开始查资料」「下面输出 MD 供确认」。
- **分步**：用户可说「先只做到 MD」「我改完 MD 了，直接生成 HTML」；按指令执行，不强制四步走完。
- **预填**：可提供「复制填空一次发给我」说明，模板见 [reference.md](reference.md)「五、信息预填模板」。

---

## 阶段一：信息收集（完成度百分比）

**必采字段与权重**：见 [reference.md](reference.md)「一、信息收集必采清单」。目标 **≥85%** 再进入阶段二。

- **完成度** = 已明确字段权重之和；未提及计 0。不足则追问并标出「仍缺：xxx」。
- **每轮必须**给出当前完成度，示例：
  ```
  📊 信息完成度：70%
  已明确：目的地、日期与天数、季节、偏好类型
  仍缺：交通节点、必去清单、特殊需求
  ```
- **追问**：一次 1～3 项，避免一大串。用户说「随便/你定」可按默认计入，后续搜集再补。

---

## 阶段二：资料搜集

**执行顺序**：**先按日、再按当日时间段**推进；每段时间的检索内容（景点/餐厅/交通/开放时间/人均/预约/避坑等）**不可缺失、尽可能全面**，以写满「核心行动 + 最优项 + ≥3 备选」。

**渠道**：先判**国外/国内**，再选用 [reference.md](reference.md)「六、搜索渠道分类」6.1 或 6.2；同类型按优先级选用。重要信息（开放时间、门票、预约）**官方 + 1 个 OTA/攻略**两处交叉验证。检索式见「七、精准检索式建议」+「目的地 + 年份 + 关键词」。

**输出**：每条可写进攻略的要点标注**来源与时效**（如「据 TripAdvisor 2025」「小红书近期」）。使用 `WebSearch`、`mcp_web_fetch` 等整理成可写入要点。

---

## 阶段三：输出 MD 与用户确认

### 结构

- **导航**：标题下「目录」，锚点链到每日 `## 🗓️ 月/日`。
- **标题/副标题**：目的地 + 时间范围 + 一句话主题。
- **行程概览表**：每行「日期 + 当日主题」。
- **一页速览**（可选）：表格「日期 | 早餐 | 上午 | 午餐 | 下午 | 晚餐 | 备注」，每格具体时间段或一句话。
- **重要提示**：3～5 条（防盗/退税/预约/交通/文化等）。
- **每日区块**：按天分节，每天内**按时间段分块**，每块独立写（见上方原则）。

### ⚠️ 每段时间块（硬性）

- **时间**：必须「HH:MM – HH:MM」。**禁止**「早上」「上午」「下午」「晚上」「中午」「傍晚」「清晨」。
- **半天**：拆成 **≥2 段**（如 13:30–15:30、16:00–18:00）。
- **内容**：核心行动（一句）+ 最优项（店名/理由/位置/人均或票价/评分 ⭐）+ **备选行动项 ≥3 个**（同类型，格式一致）。每天覆盖早/午/晚与景点；全篇统一图标 ⏰📍💰⚠️📸🔗。
- **地点**：境内高德 `[地点名](https://uri.amap.com/search?keyword=地点名)`，境外 Google 或「**地点名**」+📍；格式详见 [reference.md](reference.md)「四、地图链接规则」。

### 输出与确认

- 将完整攻略写入用户指定目录的 `.md` 文件。
- 告知用户：「请确认内容与时间段、地点、餐厅是否需增删改；确认后再进行阶段四生成 HTML。」

---

## 阶段四：生成 HTML

- **配色**：按目的地类型与季节选用 [reference.md](reference.md)「二、目的地与季节配色表」一套变量，整页统一。
- **结构**：`lang="zh-CN"`，viewport；首页元信息卡片（可选）+ 概览卡片 + 重要提示；每日 `day-section`，多段 `time-block`；地点境内用高德 `<a class="loc">`，境外用 `openMap()`，见 reference 四；返回顶部、锚点平滑滚动、移动端友好。复用 snow/anti-theft 的 CSS 类名，仅替换颜色与内容。
- **可选模块**：交通时刻小表、预算汇总、紧急联系、图片位（`img/` + `loading="lazy"`）。详见 [reference.md](reference.md)「九、HTML 丰富度与可选模块」。
- 生成后将 `index.html` 放于与 MD 同目录，提示用户可浏览器打开。

---

## 简要流程小结

1. **阶段一** → 必采字段追问，每轮给完成度；**≥85%** 进入阶段二。
2. **阶段二** → **逐日、逐段**检索；每段内容**不缺失、尽可能全**；渠道见 reference 六（国外/国内），重要信息两处验证。
3. **阶段三** → **逐日、逐段**写 MD；时间必为 HH:MM–HH:MM，半天≥2 段，每段**≥3 备选**；用户确认后再继续。
4. **阶段四** → 按 reference 二选配色，生成单页 HTML，境内高德、境外 Google。

更多细节（必采清单、配色表、MD/HTML 模板、检索式）见 [reference.md](reference.md)。
