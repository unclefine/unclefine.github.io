# 旅游攻略生成器

**目标**：理解用户需求，产出符合用户需求的旅游攻略（逐日、逐段、信息完整、可执行、附每日交互地图）。

**流程**：目的地推荐（可选）→ 信息收集（多轮+完成度）→ 资料搜集 → MD 输出与确认 → HTML 生成。

---

## ⚠️ 执行原则（必须遵守）

| 原则 | 必须 | 禁止 |
|------|------|------|
| **逐日** | 一天一天做，每天独立行程区块与时间段 | 合并多日为「几天概览」或省略某天 |
| **逐段** | 每天内一个一个时间段分开执行（搜集与输出均按段推进） | 半天或一天笼统写成一段 |
| **每段完整** | 每段含：核心行动、最优项（名称/理由/位置/人均或票价/开放时间）、**≥3 个备选**（至少 1 个与最优项不同活动类型）、📍💰⚠️；涉及交通/预约/避坑的必须检索并写入 | 缺核心行动、最优项或备选不足 3 个；备选全为同质化替代；模糊时间段 |
| **坐标** | 阶段二搜集每个活动地点时，同步确认经纬度坐标（境内 GCJ-02/高德，境外 WGS-84） | 坐标缺失或坐标系错误 |

**时间段格式**：一律「HH:MM – HH:MM」；半天拆成 **≥2 段**。详见阶段三。

---

## 易用性

- **触发**：「帮我做 xxx 攻略」「按攻略 skill 来」→ 已知目的地直接进阶段一；「不知道去哪」「推荐几个地方」→ 先走阶段零。
- **阶段话术**：切换时明确告知，如「信息已够，开始查资料」「下面输出 MD 供确认」。
- **分步**：用户可说「先只做到 MD」「我改完 MD 了，直接生成 HTML」；按指令执行，不强制四步走完。
- **预填**：可提供「复制填空一次发给我」说明，模板见 [reference.md](reference.md)「五、信息预填模板」。

---

## 阶段零：目的地推荐（可选）

**触发条件**：用户未知目的地，如「不知道去哪」「推荐几个地方」「五一 4 天假去哪好」。

1. **收集约束**（一次性询问，不超过 2 轮）：
   - 出发城市、可用天数、出行日期/季节、大致预算档次
   - 同行人群（独行/情侣/朋友团/亲子）、偏好标签（海岛/古城/雪山/美食/自然/购物等）
   - 是否有体力/健康限制、是否需要签证（出境）

2. **搜索 + 推荐**：基于约束搜索当季目的地，给出 **3～5 个方案**，每个方案包含：
   - 目的地名称 + 一句话卖点
   - 建议天数、大致预算区间（人均）
   - 当季核心亮点（≥2 条）
   - 与出发城市的交通方式与大致时长/费用

3. **用户选定后**：自动将选择结果（目的地、日期、人群、偏好等）灌入阶段一，跳过重复提问，仅追问仍缺字段。

---

## 阶段一：信息收集（完成度百分比）

**必采字段与权重**：见 [reference.md](reference.md)「一、信息收集必采清单」。目标 **≥85%** 再进入阶段二。

- **完成度** = 已明确字段权重之和；未提及计 0。不足则追问并标出「仍缺：xxx」。
- **每轮必须**给出当前完成度，示例：
  ```
  📊 信息完成度：70%
  已明确：目的地、出发城市、日期与天数、偏好类型、同行人群
  仍缺：交通节点、必去清单、特殊需求
  ```
- **追问**：一次 1～3 项，避免一大串。用户说「随便/你定」可按默认计入，后续搜集再补。

---

## 阶段二：资料搜集

**执行顺序**：**先按日、再按当日时间段**推进；每段时间的检索内容（景点/餐厅/交通/开放时间/人均/预约/避坑/坐标等）**不可缺失、尽可能全面**，以写满「核心行动 + 最优项 + ≥3 备选」。

**渠道**：先判**国外/国内**，再选用 [reference.md](reference.md)「六、搜索渠道分类」6.1 或 6.2；同类型按优先级选用。重要信息（开放时间、门票、预约）**官方 + 1 个 OTA/攻略**两处交叉验证。检索式见「七、精准检索式建议」+「目的地 + 出行年份 + 关键词」。

**输出**：每条可写进攻略的要点标注**来源与时效**（如「据 TripAdvisor 2026」「小红书近期」）。使用 `WebSearch`、`mcp_web_fetch` 等整理成可写入要点。

**⚠️ 四项新增规则（必须遵守）**：

1. **坐标搜集**：每个活动地点必须同步确认经纬度坐标。境内从高德地图获取（GCJ-02 坐标系），境外从 Google Maps 或 OpenStreetMap 获取（WGS-84）。坐标格式：`[lat, lng]`，写入阶段三对应段落备注中。

2. **节假日/节庆影响**：若出行日期覆盖法定节假日（春节/五一/十一/清明等）或当地重要节庆，必须搜索：热门景区人流与应对策略、门票/住宿节假日溢价、特殊闭馆或限流政策、节日专属活动。

3. **天气备选**：对行程中以户外活动为主的时间段，搜索对应室内替代选项（博物馆/商场/室内市场/特色餐厅/SPA 等），供阶段三雨天方案使用。

4. **多方案判断**：若行程中存在关键分歧点（如：当日来回 vs 住中转地、多个互不兼容的核心景点、不同交通方式），标记为「⚠️ 方案分歧：[分歧描述]」，阶段三中提供对比表让用户先选后展开。

---

## 阶段三：输出 MD 与用户确认

### 结构

- **导航**：标题下「目录」，锚点链到每日 `## 🗓️ 月/日`。
- **标题/副标题**：目的地 + 时间范围 + 一句话主题。
- **行程概览表**：每行「日期 + 当日主题」。
- **一页速览**（可选）：表格「日期 | 早餐 | 上午 | 午餐 | 下午 | 晚餐 | 备注」，每格具体时间段或一句话。
- **重要提示**：3～5 条（防盗/退税/预约/交通/文化等）。
- **出发前准备清单**：分组列出预订项/必备 App/行李/证件/出发当天 checklist，模板见 [reference.md](reference.md)「十、出发前准备清单模板」。
- **每日区块**：按天分节，每天内**按时间段分块**，每块独立写（见上方原则）；**每天末尾**附「☔ 雨天/恶劣天气替代方案」块。
- **信息时效声明**：文末注明「本攻略信息检索于 YYYY-MM-DD，出发前建议复核门票/开放时间/预约要求」，日期填写实际检索日期。

### ⚠️ 每段时间块（硬性）

- **时间**：必须「HH:MM – HH:MM」。**禁止**「早上」「上午」「下午」「晚上」「中午」「傍晚」「清晨」。
- **半天**：拆成 **≥2 段**（如 13:30–15:30、16:00–18:00）。
- **内容**：核心行动（一句）+ 最优项（店名/理由/位置/人均或票价/评分 ⭐）+ **备选行动项 ≥3 个**（其中至少 1 个与最优项不同活动类型）。每天覆盖早/午/晚与景点；全篇统一图标 ⏰📍💰⚠️📸🔗。
- **坐标备注**：每个最优项名称后紧跟坐标注释，格式：`<!-- coords: [lat, lng] -->`，供阶段四地图提取。
- **地点**：境内高德 `[地点名](https://uri.amap.com/search?keyword=地点名)`，境外 Google 或「**地点名**」+📍；格式详见 [reference.md](reference.md)「四、地图链接规则」。

### ⚠️ 方案分歧处理

若存在「⚠️ 方案分歧」，在 MD 中插入对比表（见 [reference.md](reference.md)「十一、方案对比表模板」），**等待用户选定方案后**再展开该段行程详情，不提前写两套完整行程。

### 输出与确认

- 将完整攻略写入用户指定目录的 `.md` 文件。
- 告知用户：「请确认内容与时间段、地点、餐厅是否需增删改；确认后再进行阶段四生成 HTML。」

---

## 阶段四：生成 HTML

- **配色**：按目的地类型与季节选用 [reference.md](reference.md)「二、目的地与季节配色表」一套变量，整页统一。
- **结构**：`lang="zh-CN"`，viewport；首页元信息卡片（可选）+ 概览卡片 + 重要提示 + 出发前准备清单；每日 `day-section`，多段 `time-block`；地点境内用高德 `<a class="loc">`，境外用 `openMap()`，见 reference 四；返回顶部、锚点平滑滚动、移动端友好。
- **每日交互地图**：每个 `day-section` 顶部嵌入 Leaflet.js 交互地图，实现序号标记 + 方向路线 + 地图/列表双向联动 + 一键导航。完整实现规范见 [reference.md](reference.md)「十二、每日交互地图实现规范」。
- **HTML 交互增强**：
  - 每个 time-block 含「✓ 已完成」勾选按钮（localStorage 持久化，刷新不丢失）
  - 页面加载时根据当前日期自动高亮/滚动到对应 day-section
  - 地图标记与列表 time-block 双向联动（点标记→列表滚动高亮；点时间块→地图飞行高亮）
- **可选模块**：交通时刻小表、预算汇总、紧急联系、图片位（`img/` + `loading="lazy"`）。详见 [reference.md](reference.md)「九、HTML 丰富度与可选模块」。
- 生成后将 `index.html` 放于与 MD 同目录，提示用户可浏览器打开。

---

## 简要流程小结

0. **阶段零**（不知目的地）→ 收集约束 → 搜索推荐 3-5 方案 → 用户选定后灌入阶段一。
1. **阶段一** → 必采字段追问（含出发城市、同行人群），每轮给完成度；**≥85%** 进入阶段二。
2. **阶段二** → **逐日、逐段**检索；同步搜集坐标；检查节假日影响；搜天气备选；标记方案分歧；渠道见 reference 六（国外/国内），重要信息两处验证。
3. **阶段三** → **逐日、逐段**写 MD；时间必为 HH:MM–HH:MM，半天≥2 段，每段**≥3 备选**（含异类）；坐标备注写入；每天末尾雨天方案块；出发前准备清单；信息时效声明；方案分歧先对比后展开；用户确认后再继续。
4. **阶段四** → 按 reference 二选配色，生成单页 HTML，境内高德、境外 Google；每日嵌入 Leaflet 交互地图；HTML 交互增强（进度勾选/当日高亮/地图列表联动）。

更多细节（必采清单、配色表、MD/HTML 模板、检索式、地图实现规范）见 [reference.md](reference.md)。
